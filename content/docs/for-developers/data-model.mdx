## Data Model

All types are defined in `src/lib/types.ts` and map directly to Supabase (PostgreSQL) tables.

### Core Entities

#### Spark

A **Spark** is the top-level workspace — a container for collecting and organizing related information around a topic or project.

```typescript
interface Spark {
  id: string;           // UUID
  name: string;         // User-given name
  description: string | null;
  status: 'active' | 'archived';
  metadata: Record<string, unknown>;
  created_at: string;   // ISO 8601
  updated_at: string;
}
```

#### SparkItem

A **SparkItem** is a piece of collected content within a Spark. It's the fundamental unit of data in the system. Each item has a type, content, and an optional vector embedding for semantic search.

```typescript
type ItemType =
  | 'link'                // Web page with scraped content
  | 'image'               // Uploaded or linked image
  | 'text'                // Raw text input
  | 'file'                // Uploaded file
  | 'note'                // Markdown note
  | 'google_drive'        // Google Drive document
  | 'slack_message'       // Saved Slack thread
  | 'contentstack_entry'  // CMS entry
  | 'contentstack_asset'  // CMS asset (file/image)
  | 'clarity_insight';    // Microsoft Clarity analytics

interface SparkItem {
  id: string;
  spark_id: string;       // FK to Spark
  type: ItemType;
  title: string;
  content: string | null; // Full text content
  summary: string | null; // AI-generated summary
  metadata: SparkItemMetadata;
  embedding: number[] | null; // 1024-dim Voyage AI vector
  created_at: string;
  updated_at: string;
}
```

The `metadata` field is a polymorphic JSON column whose shape depends on `type`:

| Item Type | Key Metadata Fields |
|-----------|-------------------|
| `link` | `url`, `og_title`, `og_description`, `og_image`, `favicon`, `scraped_images` |
| `image` | `image_url`, `image_analysis` (OCR, objects, scene, description) |
| `google_drive` | `drive_file_id`, `drive_mime_type`, `drive_web_view_link`, `drive_thumbnail_url` |
| `slack_message` | `slack_channel_name`, `slack_thread_ts`, `slack_message_count`, `slack_permalink` |
| `contentstack_entry` | `cs_stack_name`, `cs_content_type_title`, `cs_entry_uid`, `cs_entry_url` |
| `contentstack_asset` | `cs_asset_uid`, `cs_asset_url`, `cs_asset_content_type`, `cs_asset_file_size` |
| `clarity_insight` | `clarity_metric_name`, `clarity_dimensions`, `clarity_num_days` |

#### ChatMessage & ChatSession

Chat messages belong to sessions, which belong to Sparks. Sessions have their own embeddings (computed from all user messages combined) for cross-conversation semantic search.

```typescript
interface ChatMessage {
  id: string;
  spark_id: string;
  session_id: string | null;
  role: 'user' | 'assistant' | 'system';
  content: string;
  metadata: Record<string, unknown>;
  created_at: string;
}

interface ChatSession {
  id: string;
  spark_id: string;
  title: string;
  user_messages: string[];    // Denormalized for embedding
  metadata: Record<string, unknown>;
  created_at: string;
  updated_at: string;
  message_count?: number;
  last_message_preview?: string;
}
```

#### GeneratedArtifact

Artifacts are the output of the synthesis process — structured business content generated from collected items.

```typescript
type ArtifactType = 'cms_entry' | 'campaign_brief' | 'custom';

interface GeneratedArtifact {
  id: string;
  spark_id: string;
  type: ArtifactType;
  title: string;
  content: CmsEntryContent | CampaignBriefContent | Record<string, unknown>;
  status: 'draft' | 'published' | 'archived';
  metadata: Record<string, unknown>;
  created_at: string;
  updated_at: string;
}
```

**CMS Entry content** includes title, body, URL, SEO fields, and optional featured image. **Campaign Brief content** includes objective, target audience, key messages, channels, timeline, KPIs, and creative direction.

### Embedding Strategy

Embeddings are 1024-dimensional vectors generated by Voyage AI's `voyage-multimodal-3` model. They power three types of vector search via Supabase RPC functions:

| RPC Function | Table | Purpose |
|-------------|-------|---------|
| `match_spark_items` | `spark_items` | Find items semantically related to a query |
| `match_chat_sessions` | `chat_sessions` | Find relevant past conversations |
| `match_web_research_items` | `web_research_items` | Find saved web research |

All three use cosine similarity with a configurable threshold (typically 0.25) and return results ranked by similarity score.

Items are embedded when created or updated. Chat sessions are embedded asynchronously after each conversation turn (via `POST /api/chat/embed`). This means the RAG context improves over time as more conversations happen.

### Canvas State

The visual canvas stores layout and grouping information:

```typescript
interface CanvasState {
  nodePositions: Array<{
    itemId: string;
    x: number;
    y: number;
  }>;
  groups: Array<{
    id: string;
    name: string;
    itemIds: string[];
    color: string;
    embedding: number[] | null;  // Group can be searched too
    sessionId: string | null;    // Links to group chat
  }>;
}
```

Canvas groups can have their own chat sessions, allowing focused conversations about specific subsets of items.
